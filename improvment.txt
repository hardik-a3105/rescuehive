# RescueHive UI Improvements — Settings, AI Reports & Fixed Sidebar

Improve the existing RescueHive frontend by refining the **System Settings page, AI Reports page, and sidebar layout**. First inspect the existing code and API integration, then modify the current implementation without rebuilding the application.

### 1. System Settings
- Keep the existing dark tactical theme and add a fully functional light theme.
- Make **Save Preferences** persist settings through the backend or local storage where appropriate. Show success/error feedback and restore saved preferences after refresh.
- Make operator name, email, agency, refresh interval, and measurement units editable where appropriate. Display role as read-only unless role management is supported.
- Add practical preferences for notifications, sound alerts, and compact dashboard mode.
- Apply metric/imperial units and polling intervals consistently across the application.
- Validate inputs and clearly indicate unsaved changes. Do not show success if saving fails.

### 2. AI Reports
- Improve readability with clearer spacing, consistent typography, and responsive report sections.
- Add report filters for mission, date, and status, plus loading, empty, and error states.
- Include a **Generate Report** action only if supported by the existing backend; otherwise, show an appropriate unavailable state.
- Make Print / Save PDF work using browser printing or an existing PDF feature.
- Display explored area, duration, detections, and hazards using actual API data. Never invent report findings.
- Clearly label AI recommendations as advisory and require human verification. Do not present AI-generated victim triage or extraction instructions as confirmed facts.

### 3. Fixed Sidebar and Layout
- Keep the left sidebar fixed/stationary while the main content scrolls independently.
- Keep the top navigation/header stable if appropriate, without covering content.
- Make the sidebar full-height (`100vh`), with its own scrolling only when its contents exceed the viewport.
- Prevent horizontal overflow and ensure the layout works on smaller screens.
- Preserve navigation links, active-page highlighting, badges, and API status indicators.

### 4. Important Requirements
- Reuse existing components, styling, API services, authentication, and FastAPI endpoints.
- Do not replace real backend data with mock data or create duplicate API endpoints unnecessarily.
- Test theme switching, preference persistence, report printing, responsive layout, and sidebar scrolling.
- At the end, summarize the files changed, features completed, and any backend functionality still missing.

**Goal:** Make RescueHive feel like a reliable, polished disaster-response command dashboard, with working settings, readable AI reports, and stable navigation.
